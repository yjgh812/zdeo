# 框架级 issue#0203 结案报告：stop_loss「异常触发」= 票级合并持仓语义（非 bug）

> 主人裁决单独立项排查（2026-10-19）。只读排查+运行时打点（monkey-patch，零框架文件修改）。
> 产物：`analysis/bt_full_report_ladder_debug_20261019.py`（debug fork 生成器）、`reports/backtest_full_20261019_ladder_debug/`（debug 回放产物）。

## 一、疑点还原

生产 trades 2026-02-03 两笔（601668 建筑 -2.21%、601186 铁建 -5.71%，均为 2026-01-22 买入批次）标注 stop_loss，但按各自买入价手算浮亏（-2.16%/-5.69%）远不到 -8% 阈值，且已排除：逐票止损（微复现浮亏最深-2.97%）、组合熔断（2026 risk_control=0 笔）、多批合并（当时以为各自单批）。

## 二、破案：排查盲区在"按买入年过滤"

0203 实际是**建筑+铁建两只票的全部历史批次整票清理，共 13 笔**：
- 铁建 6 批（2025-01-22/04-02/07-10/10-20/12-19/2026-01-22 买入，净亏 -12.36~-5.71%），合并 avg_cost≈7.511 → 0203 收盘 6.8386 → **合并浮亏 -8.29% ≤-8%，触发合法**（ENQUEUE 运行时打点权威值 -8.2857%）。
- 建筑 7 批（2025-05-08~2026-01-22，净亏 -13.18~-2.21%），同理合并浮亏 ≤-8% 触发。
- 此前取证按"2026 年买入"过滤台账，漏掉 2025 年买入、2026 年 2 月才被清的同票批次——**"两笔异常"实为"13 笔整票清理事件"的两个切面**。

## 三、机制定性（非 bug，语义澄清）

V4.2 框架 `Portfolio.positions` 按 code 聚合，`avg_cost` 为全批次加权成本；strategy.py 止损段按 **Position（票级）** 判定 `合并浮亏 ≤ -8%` → `_enqueue_sell(code)` 整票卖出 → 各批次各自入账、同标 stop_loss。

**"-8% 硬止损"的真实语义 = 该票加权平均成本的合并浮亏止损**，非每笔买入的浮亏止损。与全史 260 笔 stop_loss 的结构完全自洽：155 笔真止损（单批或合并均≤-8%）+ 105 笔"净亏>-8%"批次（同票合并触发时被连带清理的批次，含 +11.94% 正收益批次）。

## 四、真实边界发现（呈请态，不动手）

**止损距离失真效应**：在"在榜续持"换仓机制下，老批次长期在仓摊定 avg_cost；新批次买入时**继承该票的合并浮亏状态**——若合并浮亏已接近 -8%，新批次从第一天起实际止损距离就远小于名义 -8%（极端时买入当日即触发）。2026 年初 0129/0203/0204 三次整票清理（兴业/铁建+建筑/苏农）均属此机制，发生在市场普跌段。

改进候选（**撞框架 owner=D:\workbuddyspace，只呈请不执行**）：
- a) 止损判定改为按"近 N 期批次成本"或"信号日以来价格回撤"（消除老批次摊定效应）；
- b) 或维持现状，仅在台账解读规则中固化"同日同票多批次 stop_loss = 一次整票清理事件"（零代码改动，推荐）。
- 任一改动须 fork 回测对照（stop_loss 语义变更=出场规则变更，按协议走样本外）+ 主人批准。
