## 一、命题重写（对原执行设计的勘正）

原设计假设"pit_avail_date 上游 = 底仓公告日"。**实况推翻该前提**：
`stock_factors_fundamental.pit_avail_date`（dragon_quant.db，1602 万行，111 报告期 1994-2026）
是**纯日历推导的法定披露截止**（Q1→当年0430 / H1→当年0831 / Q3→当年1031 / 年报→次年0430），
与任何公告日数据源无关（抽样 120 键全局映射零错配实锤）。

因此 1-B 真命题 = **安全性质检验**：BaoStock 实际公告日 pubDate ≤ pit_avail_date，
违反即存在前视窗口。这一架构的意外收益：PIT 可用日**不依赖任何公告日源**，天然免疫公告日源漂移；
残余风险仅"延迟披露"（实际公告晚于法定截止）。

## 二、T1 安全性质检验（主判据）

| 指标 | 值 |
|---|---|
| 对拍键（15 在市股 × 8 报告期） | 120 |
| baostock pubDate 缺失 | 0 |
| **前视违反（pubDate > pit_avail_date）** | **0** |
| 保守度 pit_avail − pubDate | 中位 **3 天** / 最小 0 / 最大 51 天 |
| pit_avail 与纯日历法定映射错配 | 0/120 |

解读：保守 PIT 约定下**零前视**；实际披露中位只比法定截止早 3 天，保守化的可用性代价中位 3 天（最大 51 天为年报早披个案，属"最保守"设计意图）。
