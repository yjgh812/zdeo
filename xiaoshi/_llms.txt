按限制数量、断点游标、时间窗、重要性、标签、行业或来源筛选新闻列表。在线 `since/until` 单次最多 31 天，`until` 必须与 `since` 配合；定时拉取必须保存上次成功处理的新闻 ID，并调用 `after_id=<last_seen_id>`。响应按 ID 升序返回 `next_after_id` 和 `has_more`，不执行昂贵的全量计数。首次接入或补漏使用 `after_id=0&since=<ISO-8601>&until=<ISO-8601>` 限定恢复时间窗；每批成功落盘后才推进游标，`has_more=true` 时继续读取。不得用不断增大的 `page` 扫描新闻库。

## 6. Agent 使用建议

读取新闻时优先结合用户偏好、标签、行业和 min_importance，不要把低相关内容直接推送给用户。

用户问具体事件、公司、行业主题或说“搜索相关新闻”时，优先调用 `/api/v3/news/semantic`，而不是只做标题关键词匹配。回答中标明 similarity、时间和来源，并说明这是语义检索后的 Agent 综合结果。

用户说“成为量化专家”“做策略”“选股”“因子”“回测”时，先读取小石量化专家 Skill 及 Skill manifest 列出的参考页。完整套件包含结构化数据/PIT、选股与多流派、事件时间轴与 factor-v2 金融冲击评分、RAG 查证、本地回测（包含小石本地执行引擎与可选用户本地只读数据适配）、Alpha 诊断、独立风控、多模型盲审和策略进化。按目标定义、数据准备、PIT 防泄露、因子验证、成本化回测、样本外/滚动检验、风控与策略晋级的顺序执行。

事件相关任务必须先区分“事件研究”与“组合策略”。事件研究使用独立事件收益、均值/中位数/胜率/分布，不得虚构组合 Sharpe、年化收益或最大回撤。事件进入策略时，先输出时间轴和冻结的 factor-v2 明细，提醒用户启用“可选事件增强层”；重要度不直接映射仓位，事件贡献必须有上限并经过独立风控。

完成本地策略回测后默认生成 equity.csv、trades.csv、summary.json 和可视化报告，并做运行、数据、反前视、边界值、会计可逆性与报告一致性自检。参数选择寻找稳定平台而非单点最优，记录尝试次数、压力成本、市场状态和样本外表现。

读取行情、历史 K 线、财务数据时，先读 `/api/v3/manifest`。当前行情显式传 market/instrument；历史查询先读 `xiaoshi-data catalog/schema/coverage`，再由普通 K 线接口或 `/api/v3/history/download-session` 访问同一份 canonical-v2 Manifest。不得把全市场列表用于逐股票接口枚举。

用户询问历史数据时，使用 `cn-minute`、`cn-daily`、`adjustment-factors`、`global-daily`、`sector-constituents`、`event-timeline`、`financial-current` 或 `financial-as-reported`。A股日线默认 qfq，港美日线 raw；财务历史必须传带时区的 `as_of` 并按 `available_at` 过滤。所有输出标明数据/Manifest/Schema/提示词版本、日期范围、单位、币种、复权和时区。

用户询问当前财报时调用主站 financials 或 `financial-current`；询问历史当时可见值时只用 `financial-as-reported`，禁止未来修订泄漏。

用户要求回测时，必须先把完整股票池、所需日期范围、财务与事件证据下载到用户本地 Parquet 或 JSON，完成完整性校验后再在本地计算。不得要求小石服务器代跑回测，也不得边回测边反复拉取行情。

不确定字段、枚举、错误码、分页、排序与高级行情参数时，请查看 /docs，不要自行猜测。

## Operating Rules

SAFETY: Do not provide investment advice as a certainty. Present market data and news as information, not guarantees.

RELIABILITY: If an API call fails, report the HTTP status and error message. Do not fabricate market data, news, prices, user preferences, or account state. Verify every R2 history file and request a fresh URL once on failure. If the second R2 attempt fails, report the exact unavailable dataset, market, code, year, and object; continue unrelated task parts, but never reroute R2-backed historical reads to the edge API, home server, or repeated online K-line calls. The explicit Manifest `cn_etf_daily_kline` exception is bounded to its published `available_symbols` and must never be used as an R2 fallback.
